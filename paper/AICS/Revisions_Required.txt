PRIORITY 2 - CRITICAL / MUST FIX
CALCULATE AND REPORT THE THEORETICAL-CONSISTENCY INDICATOR

Concern raised
ICTAI Reviewer 4 noted that the consistency indicator is arguably one of the most distinctive parts of the workflow, but the submitted paper defined it and never reported it.

Why this matters
The AICS prototype claim is diagnostic and architectural. Reporting consistency directly tests whether decomposition exposes contradictions that a one-shot classification would hide. This result is more central to the prototype paper than adding another broad benchmark.

Definition already in the paper
q_i^(s) = 1[ strategy-predicted rank = theory-implied rank ].

Implementation steps
1. For each completed staged run, retrieve:
   - delegation output d_hat;
   - authority output a_hat;
   - constraint output c_hat;
   - strategy-specific predicted rank y_tilde.
2. Reconstruct the theory-implied rank y_map using the deterministic codebook mapping already implemented in the workflow:
   - no delegation -> 0;
   - delegation + Low authority + Strong constraints -> 1;
   - delegation + Low authority + Weak constraints -> 2;
   - delegation + High authority + Strong constraints -> 3;
   - delegation + High authority + Weak constraints -> 4.
3. For each eligible case, set q=1 when y_tilde equals y_map and q=0 otherwise.
4. Do not assign q to a case missing any component needed for y_map or missing the strategy rank. Mark that case incomplete for this calculation and report the denominator.
5. Do not calculate this measure for the unconstrained one-shot baseline unless that baseline actually generated the same component variables. In the current design it does not, so Table 5 correctly uses -- for one-shot consistency.
6. For each model x staged-strategy configuration calculate:
   - number consistent = sum(q);
   - denominator = number of complete eligible cases;
   - consistency rate = sum(q) / denominator.
7. Prefer calculating the consistency rate on the same common case set used for the corresponding performance comparison. If a separate denominator is unavoidable, state it explicitly.
8. Spot-check at least five q=0 cases against the stored execution traces to verify that the mismatch is real and not a joining/coding error.
9. Fill every * in the Consist. column with the calculated rate (and, if space permits, report count/N in a note or supplementary analysis file).
10. Update Section 5.3 only after the calculations. Report the observed range and identify high/low configurations only if the calculated values support those descriptions.

Required output for paper
- Consistency numerator, denominator, and rate for every model x staged-strategy cell.
- A file listing all inconsistent law IDs, y_tilde, y_map, and the component values producing y_map.
- Updated Table 5 consistency column.
